## 3. Flash 与 RAM 分区

| 区域 | 起始地址 | 长度 | 说明 |
| --- | --- | --- | --- |
| RAM | `0x20000000` | 32 KiB | STM32G431CBU6 SRAM |
| 应用 FLASH | `0x08002000` | `0x1B7FC`，112636 B | 避开前部 Bootloader 和末尾保留区 |

应用地址同时由链接脚本和 `APPLICATION_ADDRESS` 定义为 `0x08002000`。后续不得单独修改其中一处。

## 5. 当前编译警告基线

当前 Debug 和 Release 均能链接，但存在以下已确认警告类别：

- `myadc.c` 两个查询函数可能返回未初始化值。
- `u8g2_disp_fun.c` 有 `int32_t` 与 `%d` 不匹配，以及多处无效局部变量。
- `button.c`、`tle5012b.c`、`main.c`、`fdcan.c` 存在无效局部变量。
- `motordriver.c` 存在未使用的静态函数。
- `flash.c` 存在反斜杠结尾的多行注释警告。

这些警告在后续独立提交中处理；迁移基线不顺带修改业务源码。

## 6. Classic CAN 帧基线

当前应用使用 Classic CAN、29 位扩展 ID 和固定 8 字节发送帧。

```text
identifier = (cmd_id << 24) | (option << 8) | can_id
cmd_id     = identifier[28:24]
cmd_para   = identifier[23:16]
can_id     = identifier[7:0]
```

当前接收实现将 `identifier[15:8]` 作为响应相关的低 8 位 option 使用。`identifier[23:16]` 同时由 `cmd_para` 读取；在正式协议位域表冻结前不得改变这一行为。

### 6.1 已占用命令

| `cmd_id` | 当前行为 |
| ---: | --- |
| `0` | 设备发现/ID 响应 |
| `3` | 电机输出使能 |
| `4` | 电机输出关闭 |
| `7` | 修改 CAN ID |
| `9` | 清除堵转保护状态 |
| `10` | 请求保存 Flash 配置 |
| `11` | 修改 CAN 波特率档位 |
| `12` | 启用堵转保护 |
| `13` | 关闭堵转保护 |
| `14` | 启用位置超范围保护 |
| `15` | 关闭位置超范围保护 |
| `17` | 按 `func_index` 读取本机参数 |
| `18` | 按 `func_index` 写入本机参数 |
| `19` | 通过本机读取下游 I2C 功能参数 |
| `20` | 通过本机写入下游 I2C 功能参数 |
| `21` | 下游 I2C 原始读取 |
| `22` | 下游 I2C 原始写入 |

`cmd_id = 2` 被多个控制命令用作状态响应。未在表中出现的编号不能视为可直接分配，必须先核对正式协议文档和主机库。

### 6.2 通用功能帧

当前 `cmd_id = 17/18` 使用以下 8 字节数据布局：

```text
byte 0..1  func_index，uint16，小端
byte 2..3  保留/现有透传内容
byte 4..7  func_data，int32，小端
```

现有功能索引覆盖开关、运行模式、电流/速度/位置目标、速度/位置电流限制、速度/位置 PID、实际速度/位置/电流、旋钮计数、电压、温度和 RGB 参数。保护参数枚举虽已声明，但处理分支尚未全部实现，后续必须以正式协议为准补齐。

## 7. I2C 从机寄存器基线

| 地址 | 当前含义 |
