# M5Stack Unit RollerCAN CAN 控制协议

| 项目 | 内容 |
| :--- | :--- |
| 文档版本 | `V3.1` |
| 适用设备 | M5Stack Unit RollerCAN |
| 适用固件 | `V3` |
| 产品设备 ID | `0x02` |
| 发布日期 | `2026-08-24` |
| 文档状态 | Release |

本文档定义 Unit RollerCAN 的设备发现、电机控制、状态读取、参数访问和 CAN 转 I2C 通信协议。

---

## 1. 基本信息

| 项目 | 说明 |
| :--- | :--- |
| 总线 | CAN 2.0 Classic |
| 帧格式 | 29 位扩展数据帧 |
| 数据长度 | 固定 8 字节 |
| 默认波特率 | 1 Mbps |
| 波特率档位 | `0=1 Mbps`，`1=500 kbps`，`2=125 kbps` |
| 数据端序 | 多字节数值均为小端 |
| 应用校验 | 不另加校验；CAN 控制器负责链路 CRC |

## 2. CAN ID 与数据帧

29 位 CAN ID 按以下方式划分：

| 位段 | 含义 |
| :--- | :--- |
| bit28~24 | 通信类型 `cmd_id` |
| bit23~16 | 命令参数 `cmd_para`，或响应状态/成功标志 |
| bit15~8 | 主机 ID、当前电机 ID 或命令参数，按指令定义 |
| bit7~0 | 目标电机 ID、主机 ID 或响应电机 ID，按指令定义 |

所有数据帧均为 8 字节 Data。请求通常使用 bit15~8 标识主机、bit7~0 指定目标
电机；各响应的 ID 方向和状态字段以第 4 节为准，不可使用统一格式解析。

### 2.1 状态响应 ID

通信类型 `0x02` 的状态响应使用：

- bit23~22：系统状态，`0` 待机，`1` 运行，`2` 错误；
- bit21~19：模式，`1` 速度，`2` 位置，`3` 电流，`4` 编码器；
- bit18~16：错误位，bit16 过压、bit17 堵转、bit18 位置超范围；
- bit15~8：当前电机 CAN ID；
- bit7~0：发起查询的主机 CAN ID。

## 3. 参数索引

单参数命令使用 `0x11`/`0x12`。请求和响应中的 Byte0~1 为小端参数索引，
Byte2~3 为 `0`，参数值放在 Byte4~7（不足 4 字节时高字节为 `0`）。

| 索引 | 参数名称 | 类型/缩放 | 权限 | 说明 |
| :--- | :--- | :--- | :--: | :--- |
| `0x7002` | 保存 Flash | `uint8_t` | W | 写非零值，建议写 `1` |
| `0x7003` | 解除保护 | `uint8_t` | W | 写非零值解除堵转保护 |
| `0x7004` | 电机开关 | `uint8_t` | R/W | `0` 关，`1` 开 |
| `0x7005` | 运行模式 | `uint8_t` | R/W | `1` 速度，`2` 位置，`3` 电流，`4` 编码器 |
| `0x7006` | 电流目标 | `int32_t` | R/W | X100 mA，范围 `-120000~120000` |
| `0x700A` | 速度目标 | `int32_t` | R/W | X100 rpm |
| `0x7016` | 位置目标 | `int32_t` | R/W | X100 度 |
| `0x7017` | 位置环最大电流 | `int32_t` | R/W | X100 mA，范围 `-120000~120000` |
| `0x7018` | 速度环最大电流 | `int32_t` | R/W | X100 mA，范围 `-120000~120000` |
| `0x7020` | 速度 Kp | `uint32_t` | R/W | 实际值 = raw / 100000 |
| `0x7021` | 速度 Ki | `uint32_t` | R/W | 实际值 = raw / 10000000 |
| `0x7022` | 速度 Kd | `uint32_t` | R/W | 实际值 = raw / 100000 |
| `0x7023` | 位置 Kp | `uint32_t` | R/W | 实际值 = raw / 100000 |
| `0x7024` | 位置 Ki | `uint32_t` | R/W | 实际值 = raw / 10000000 |
| `0x7025` | 位置 Kd | `uint32_t` | R/W | 实际值 = raw / 100000 |
| `0x7030` | 速度回读 | `int32_t` | R | X100 rpm |
| `0x7031` | 位置回读 | `int32_t` | R | X100 度 |
| `0x7032` | 电流回读 | `int32_t` | R | X100 mA |
| `0x7033` | 编码器计数 | `int32_t` | R/W | 仅编码器模式使用 |
| `0x7034` | 输入电压 | `int32_t` | R | X100 V |
| `0x7035` | MCU 温度 | `int32_t` | R | 摄氏度 |
| `0x7050` | RGB 模式 | `uint8_t` | R/W | `0` 系统，`1` 用户 |
| `0x7051` | RGB 颜色 | `uint32_t` | R/W | `RGB-B + RGB-G*256 + RGB-R*65536` |
| `0x7052` | RGB 亮度 | `uint8_t` | R/W | `0~100` |
| `0x7060` | 固件版本 | `uint8_t` | R | 固定 `3` |
| `0x7061` | 产品设备 ID | `uint8_t` | R | RollerCAN 固定 `0x02` |
| `0x7062` | UID Word 0 | `uint32_t` | R | UID Byte0~3，小端 |
| `0x7063` | UID Word 1 | `uint32_t` | R | UID Byte4~7，小端 |
| `0x7064` | UID Word 2 | `uint32_t` | R | UID Byte8~11，小端 |
| `0x7065` | 当前 CAN ID | `uint8_t` | R | Byte4 返回 ID，其余高位为 `0` |
| `0x7066` | CAN 波特率档位 | `uint8_t` | R | `0/1/2` 对应三档波特率 |
| `0x7067` | 当前通信模式 | `uint8_t` | R | `1` I2C，`2` CAN，`3` CAN+I2C |
| `0x7068` | 本机 I2C 地址 | `uint8_t` | R | 7 位地址，不含读写位 |
| `0x7069` | 系统状态 | `uint8_t` | R | `0` 待机，`1` 运行，`2` 错误 |
| `0x706A` | 错误码 | `uint8_t` | R | bit0 过压，bit1 堵转，bit2 超范围 |
| `0x706B` | 堵转保护使能 | `uint8_t` | R/W | `0` 关，`1` 开 |
| `0x706C` | 位置范围保护使能 | `uint8_t` | R/W | `0` 关，`1` 开 |
| `0x706D` | 按键模式切换使能 | `uint8_t` | R/W | `0` 关，`1` 开 |
| `0x7070` | 启动编码器校准 | `uint8_t` | W | 写 `1` 触发 |
| `0x7071` | 保存编码器校准结果 | `uint8_t` | W | 写 `1` 保存 |
| `0x7072` | 编码器校准忙状态 | `uint8_t` | R | `0` 空闲，`1` 校准中 |

布尔参数写入其他值时忽略本次写入。校准保存仅在校准完成且结果有效时执行。

## 4. 通信类型与命令

### 4.1 发现、控制和保护

| Cmd | 请求 ID 字段 | Data | 响应 |
| :---: | :--- | :--- | :--- |
| `0x00` | `cmd_para=0`；bit15~8 主机 ID；bit7~0 目标电机 ID | 全 0 | `0x00` 广播响应；bit23~16=`0`，bit15~8 当前电机 ID，bit7~0=`0xFE` |
| `0x02` | `cmd_para=0`；bit15~8 主机 ID；bit7~0 目标电机 ID | 全 0，主动查询 | 返回 `0x02` 状态帧，格式见 2.1 和 5.1 |
| `0x03` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧 |
| `0x04` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧 |
| `0x07` | bit23~16 预设置 CAN ID；bit15~8 主机 ID；bit7~0 目标 ID | 全 0 | 返回 `0x00` 发现响应 |
| `0x09` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧，解除堵转 |
| `0x0A` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧，保存 Flash |
| `0x0B` | bit23~16 波特率档位；bit15~8 主机 ID；bit7~0 目标 ID | 全 0 | `0x0B`，返回当前档位 |
| `0x0C` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧，开启堵转保护 |
| `0x0D` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧，关闭堵转保护 |
| `0x0E` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧，开启位置范围保护 |
| `0x0F` | 主机 ID/目标电机 ID | 全 0 | 返回 `0x02` 状态帧，关闭位置范围保护 |

### 4.2 单参数和 I2C 参数访问

| Cmd | 请求 Data | 响应 ID | 响应 Data |
| :---: | :--- | :---: | :--- |
| `0x11` | Byte0~1 索引，Byte2~7 为 `0` | `0x11` | Byte0~1 索引，Byte2~3 为 `0`，Byte4~7 参数值；响应 ID 的 bit15~8 为主机 ID，bit7~0 为电机 ID |
| `0x12` | Byte0~1 索引，Byte2~3 为 `0`，Byte4~7 写入值 | `0x02` | 状态响应 |
| `0x13` | Byte0~1 索引，Byte2~3 I2C 地址，Byte4~7 为 `0` | `0x13` | Byte0~1 索引，Byte2~3 保留为 `0`，Byte4~7 参数值 |
| `0x14` | Byte0~1 索引，Byte2~3 I2C 地址，Byte4~7 写入值 | `0x02` | 状态响应 |

单参数访问只支持第 3 节列出的索引。参数写入掉电丢失，需另发保存命令。

### 4.3 原始 I2C 转发

| Cmd | ID 参数 | Data | 响应 |
| :---: | :--- | :--- | :--- |
| `0x15` | 主机 ID/目标电机 ID | Byte0 I2C 7 位地址；Byte1 读取长度，最大 8 | `0x15`；cmd_para=`0` 失败、`1` 成功；Data 为读取字节 |
| `0x16` | bit23 为停止条件；bit22~16 为 I2C 地址；bit15~8 为主机 ID；bit7~0 为目标电机 ID | Byte0 写入长度，最大 7；Byte1~7 写入数据 | `0x16`；cmd_para=`0` 失败、`1` 成功；Data 为 `0` |

对于 `0x15`、`0x16`，响应沿用旧协议的 ID 布局：bit15~8 为主机 ID，bit7~0
为电机 ID；请求的 bit15~8 也是主机 ID。`0x16` 的 bit23 为停止条件，bit22~16
为 I2C 地址。

### 4.4 扩展位置

#### `0x17` 设置扩展目标位置

请求和成功响应 Data：

| 字节 | 字段 | 编码 |
| :---: | :--- | :--- |
| `0 ~ 3` | 目标圈数 | 小端 `int32_t` |
| `4 ~ 5` | 圈内角度 | 小端 `uint16_t`，0.01 度，范围 `0~35999` |
| `6 ~ 7` | 位置环最大电流 | 小端 `uint16_t`，单位 mA，范围 `0~1200` |

请求 ID 的 `cmd_para` 必须为 `0`。响应 `cmd_para` 为 `0` 失败、`1` 成功，
bit15~8 为主机 ID，bit7~0 为电机 ID。三个字段完整校验后同时生效；任一字段
非法时不修改原参数，失败响应 Data 全为 `0`，成功响应回显生效数据。

#### `0x18` 读取扩展位置

请求 ID 的 `cmd_para`：`0` 读取目标位置，`1` 读取实际位置，其他值失败；bit15~8
为主机 ID，bit7~0 为目标电机 ID；Data 全为 `0`。

响应 `cmd_para` 为 `0` 失败、`1` 成功，bit15~8 为主机 ID，bit7~0 为电机 ID：

| 读取项 | Byte0~3 | Byte4~5 | Byte6~7 |
| :--- | :--- | :--- | :--- |
| 目标位置 | 目标圈数，`int32_t` | 目标圈内角度，0.01 度 | 位置最大电流，`uint16_t`，mA |
| 实际位置 | 实际圈数，`int32_t` | 实际圈内角度，0.01 度 | 实际电流，`int16_t`，mA |

读取成功时返回当前数据，失败时 Data 全为 `0`。

## 5. 状态帧数据

`0x02` 状态响应的 Data 字段为：

| 字节 | 字段 | 类型/单位 |
| :---: | :--- | :--- |
| `0~1` | 当前速度 | `int16_t`，rpm |
| `2~3` | 当前位置 | `int16_t`，度 |
| `4~5` | 当前电流 | `int16_t`，mA |
| `6~7` | 输入电压 | `int16_t`，V |

## 6. CAN ID 拼接和响应规则

主机可以按以下公式生成 29 位扩展 ID：

```text
CAN_ID = (cmd_id << 24) | (cmd_para << 16) | (option << 8) | node_id
```

其中 `option` 和 `node_id` 的含义由命令定义。请求通常使用 `option=主机 ID`、
`node_id=目标电机 ID`。

示例：主机 ID=`0x05` 向电机 ID=`0x64` 查询状态（`cmd_id=0x02`，`cmd_para=0`）：

```text
CAN_ID = (0x02 << 24) | (0x00 << 16) | (0x05 << 8) | 0x64
       = 0x02000564
Data   = 00 00 00 00 00 00 00 00
```

不同响应的 ID 规则如下：

| 响应类型 | bit23~16 | bit15~8 | bit7~0 |
| :--- | :--- | :--- | :--- |
| `0x00` 发现 | 固定 `0` | 当前电机 ID | `0xFE` |
| `0x02` 状态 | 状态/模式/错误组合 | 当前电机 ID | 查询主机 ID |
| `0x0B` 波特率 | 当前波特率档位 | 请求主机 ID | 当前电机 ID |
| `0x11`/`0x13` 参数读取 | 固定 `0` | 请求主机 ID | 当前电机 ID |
| `0x15`/`0x16` 原始 I2C | `0` 失败、`1` 成功 | 请求主机 ID | 当前电机 ID |
| `0x17`/`0x18` 扩展位置 | `0` 失败、`1` 成功 | 请求主机 ID | 当前电机 ID |

状态帧的 bit23~16 不是单一错误码，必须按第 2.1 节逐位解析。CAN ID 为扩展帧时，
主机必须设置 `IDE=Extended`，不能按 11 位标准帧发送。

## 7. 指令逐字节说明

### 7.1 发现和基本控制

所有基本控制命令的数据区均为 8 字节，未使用字节填 `0`。

| Cmd | 请求 ID | 请求 Data | 响应 |
| :---: | :--- | :--- | :--- |
| `0x00` | `cmd_para=0`，option 为主机 ID，node 为目标 ID | 全 `0` | `0x00` 发现帧；返回当前电机 ID |
| `0x02` | `cmd_para=0`，option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧；主机可主动周期查询 |
| `0x03` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，电机使能 |
| `0x04` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，电机停止 |
| `0x07` | `cmd_para` 为新 CAN ID，option 为主机 ID，node 为旧 ID | 全 `0` | `0x00` 发现帧；新 ID 立即生效 |
| `0x09` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，解除堵转 |
| `0x0A` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，保存 Flash |
| `0x0B` | `cmd_para` 为波特率档位，option 为主机 ID，node 为目标 ID | 全 `0` | `0x0B`，返回实际档位 |
| `0x0C` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，开启堵转保护 |
| `0x0D` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，关闭堵转保护 |
| `0x0E` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，开启位置范围保护 |
| `0x0F` | option 为主机 ID，node 为目标 ID | 全 `0` | `0x02` 状态帧，关闭位置范围保护 |

`0x07` 和 `0x0B` 的参数修改完成后，主机应等待响应再切换自己的 CAN ID 或波特率。
`0x0A` 会写 Flash，不应高频调用。

#### 7.1.1 发现设备 `Cmd 0x00`

请求使用 29 位扩展 ID：`cmd_para=0`、bit15~8 为主机 ID、bit7~0 为目标 ID；Data
固定为 8 个 `0x00`。发现未知 ID 的设备时，目标 ID 使用广播值 `0xFE`。

设备返回 `Cmd 0x00`，bit23~16 固定 `0`，bit15~8 为设备当前 CAN ID，bit7~0 为
`0xFE`，Data 全为 `0`。主机收到发现响应后，应再用返回的设备 ID 执行 `0x02` 定向查询。

#### 7.1.2 查询状态 `Cmd 0x02`

请求 `cmd_para=0`，bit15~8 为主机 ID，bit7~0 为目标电机 ID，Data 全为 `0`。
设备返回 `Cmd 0x02` 状态帧；响应 ID 的状态、模式、错误位见 2.1，Data 见 8.1。
主机应同时匹配响应命令、设备 ID 和主机 ID，不能仅凭收到任意 `0x02` 帧判定在线。

#### 7.1.3 开启电机 `Cmd 0x03`

请求 `cmd_para=0`，bit15~8 为主机 ID，bit7~0 为目标电机 ID，Data 全为 `0`。设备
尝试开启当前控制模式并返回 `0x02` 状态帧。过压、堵转或模式无效时，设备可能保持
关闭；主机必须根据返回的系统状态、错误位和后续反馈判断是否真正启动。

#### 7.1.4 停止电机 `Cmd 0x04`

请求 ID 与 `0x03` 相同，Data 全为 `0`。设备立即关闭电机驱动并返回 `0x02` 状态帧。
停止不会清除目标值和已保存参数，重新开启后仍使用当前模式与目标。

#### 7.1.5 修改 CAN ID `Cmd 0x07`

`cmd_para` 为新 CAN ID `0x00~0xFF`，bit15~8 为主机 ID，bit7~0 为修改前的目标 ID，
Data 全为 `0`。设备返回 `0x00` 发现格式响应，响应中携带新 ID；随后重新初始化 CAN
过滤器并自动写入 Flash。主机必须等待响应完成后再改用新 ID。

#### 7.1.6 解除堵转保护 `Cmd 0x09`

请求 `cmd_para=0`，bit15~8 为主机 ID，bit7~0 为目标 ID，Data 全为 `0`。设备清除
堵转错误、恢复计数和堵转保护状态，并返回 `0x02` 状态帧。该命令不自动开启电机。

#### 7.1.7 保存参数 `Cmd 0x0A`

请求 ID 使用主机 ID 和目标 ID，`cmd_para=0`，Data 全为 `0`。设备提交一次 Flash
保存并返回 `0x02` 状态帧。Flash 擦写寿命有限，应在一组参数修改完成后调用一次，
不要作为周期命令发送。

#### 7.1.8 修改 CAN 波特率 `Cmd 0x0B`

| cmd_para | 波特率 |
| :---: | :---: |
| `0` | 1 Mbps |
| `1` | 500 kbps |
| `2` | 125 kbps |

bit15~8 为主机 ID，bit7~0 为目标 ID，Data 全为 `0`。大于 `2` 的档位不生效。响应
仍为 `Cmd 0x0B`，bit23~16 返回设备实际采用的档位；设备在响应完成并延时约 300 ms
后切换波特率。该命令只修改运行值，需要掉电保持时再发送 `0x0A`。

#### 7.1.9 开启/关闭堵转保护 `Cmd 0x0C / 0x0D`

`0x0C` 开启，`0x0D` 关闭。请求 `cmd_para=0`、Data 全为 `0`，设备返回 `0x02`
状态帧。关闭保护不会清除已经产生的堵转错误，已有错误仍需发送 `0x09`。使用 `0x0A`
保存后掉电保持。

#### 7.1.10 开启/关闭位置范围保护 `Cmd 0x0E / 0x0F`

`0x0E` 开启，`0x0F` 关闭。请求 `cmd_para=0`、Data 全为 `0`，设备返回 `0x02`
状态帧。该设置只控制保护使能，不修改当前位置或目标位置；使用 `0x0A` 保存。

### 7.2 单参数访问数据区

#### `0x11` 单参数读取

请求 `cmd_para=0`、bit15~8 为主机 ID、bit7~0 为目标电机 ID，Data 固定 8 byte：

| 字节 | 内容 |
| :---: | :--- |
| `0~1` | 参数索引，小端 |
| `2~3` | 固定 `0` |
| `4~7` | 固定 `0` |

响应 Cmd 为 `0x11`、cmd_para=`0`，Data0~1 回显索引，Data2~3 为 `0`，Data4~7
为参数值。小于 4 byte 的参数高位固定为 `0`。未知或只写索引的返回 Data4~7 为 `0`；
主机应先确认索引在第 3 节具有读权限，再解释返回值。

#### `0x12` 单参数写入

请求 `cmd_para=0`，Data0~1 为索引，Data2~3 为 `0`，Data4~7 为小端参数值。设备
返回 `0x02` 状态帧，但该状态帧没有独立的参数写入成功位；未知索引、只读索引或非法值
可能被忽略，因此必须再用 `0x11` 回读确认。参数默认只修改运行值，使用索引 `0x7002`
或命令 `0x0A` 保存；校准启动/保存等触发型索引按第 3 节说明执行。

### 7.3 I2C 从机参数访问

#### `0x13` 读取下游 I2C 参数

请求 `cmd_para=0`，Data0~1 为第 3 节参数索引，Data2~3 为小端 I2C 7 位地址
`0x0008~0x0077`，Data4~7 填 `0`。设备按索引映射到下游 Roller 的 I2C 寄存器并读取。
响应 Cmd 为 `0x13`，Data0~1 回显索引，Data4~7 返回参数，Data2~3 固定为 `0`，
不回显请求地址。地址无效、索引不支持或 I2C 失败时数据可能为 `0`，应结合
下游设备发现和预期范围判断。

支持读取的索引为 `0x7004~0x7006`、`0x700A`、`0x7016~0x7018`、`0x7020~0x7025`、
`0x7030~0x7035`、`0x7050~0x7052`。其他索引不执行下游读取。

#### `0x14` 写入下游 I2C 参数

请求 Data0~1 为索引，Data2~3 为下游 7 位地址，Data4~7 为写入值。设备返回 `0x02`
状态帧，但不提供独立 I2C 写成功位；写入后必须用 `0x13` 回读。地址范围为
`0x08~0x77`，只读或不支持索引不生效。是否掉电保存取决于是否另写下游保存索引。

支持写入的索引为 `0x7002~0x7006`、`0x700A`、`0x7016~0x7018`、`0x7020~0x7025`、
`0x7033`、`0x7050~0x7052`。其中 `0x7002` 保存 Flash，`0x7003` 解除保护。

### 7.4 原始 I2C 访问

#### `0x15` 原始读取

请求 `cmd_para=0`，option 为主机 ID、node 为目标电机 ID。Data0 为下游 I2C 7 位
地址，Data1 为读取长度 `1~8`，Data2~7 填 `0`。响应 Cmd 为 `0x15`，cmd_para=`0`
失败、`1` 成功；成功时 Data0 起返回实际字节，未使用尾部填 `0`。地址必须在
`0x08~0x77`，长度为 `0`、大于 `8` 或总线失败均返回失败。

#### `0x16` 原始写入

请求 ID 的 bit23 为 `is_stop_bit`，bit22~16 为下游 I2C 7 位地址，bit15~8 为主机
ID，bit7~0 为目标电机 ID。Data0 为写入长度 `1~7`，Data1~7 为数据。响应 Cmd
为 `0x16`，cmd_para=`0` 失败、`1` 成功，Data 全 `0`。`is_stop_bit=0` 使用重复
起始，`1` 使用 STOP；地址无效、长度非法或总线失败均返回失败。

### 7.5 扩展位置设置：`0x17`

请求 ID 的 `cmd_para` 必须为 `0`，option 为主机 ID，node 为目标电机 ID。

| 字节 | 字段 | 类型/范围 |
| :---: | :--- | :--- |
| `0~3` | 目标圈数 | 小端 `int32_t` |
| `4~5` | 目标圈内角度 | 小端 `uint16_t`，0.01 度，`0~35999` |
| `6~7` | 位置环最大电流 | 小端 `uint16_t`，mA，`0~1200` |

响应 Cmd 为 `0x17`，cmd_para 为 `0` 失败或 `1` 成功，option 为主机 ID，node 为
电机 ID。成功时回显请求中的圈数、圈内角度和最大电流字段，失败时 8 字节 Data 全为
`0`。三个参数完整校验后同时生效；圈内角度大于 `35999`、最大电流大于 `1200 mA`
或编码器正在校准时均返回失败，且不修改原值。最大电流写入后会经过位置 PID 的电流
限幅接口，实际生效值应通过 `0x18` 的目标位置读取确认。

### 7.6 扩展位置读取：`0x18`

请求 ID 的 `cmd_para` 为 `0` 读取目标位置、`1` 读取实际位置；其他值直接失败。
option 为主机 ID，node 为目标电机 ID，Data 全为 `0`。

| 读取项 | Byte0~3 | Byte4~5 | Byte6~7 |
| :--- | :--- | :--- | :--- |
| 目标位置 | 目标圈数，`int32_t` | 目标圈内角度，0.01 度 | 位置最大电流，`uint16_t`，mA |
| 实际位置 | 实际圈数，`int32_t` | 实际圈内角度，0.01 度 | 实际电流，`int16_t`，mA |

响应 cmd_para 为 `0` 失败或 `1` 成功；失败时 Data 全为 `0`。

## 8. 状态帧字段和错误处理

### 8.1 `0x02` 状态 Data

| 字节 | 字段 | 类型/单位 |
| :---: | :--- | :--- |
| `0~1` | 当前速度 | 小端 `int16_t`，rpm |
| `2~3` | 当前位置 | 小端 `int16_t`，度 |
| `4~5` | 当前电流 | 小端 `int16_t`，mA |
| `6~7` | 输入电压 | 小端 `int16_t`，V |

该状态帧为兼容旧协议的紧凑反馈，速度、位置、电流和电压均为整数单位。需要 X100 精度
或大范围位置时，应使用 `0x11` 参数回读及 `0x18` 扩展位置回读。

### 8.2 系统状态和错误位

状态编码为 `0` 待机、`1` 运行、`2` 错误。错误位 bit16/17/18 分别为过压、堵转、
位置超范围。错误状态不会通过 CAN 控制器错误计数代替，主机应读取 ID 状态位。
需要解除堵转时发送 `0x09`，不要直接清除主机缓存中的错误位。

### 8.3 参数持久化和校准

- 普通参数写入仅修改运行值，掉电丢失；使用 `0x0A` 或索引 `0x7002` 保存。
- `0x7070` 写 `1` 启动编码器校准，轮询 `0x7072`，空闲后用 `0x7071` 写 `1` 保存。
- `0x706B~0x706D` 只接受 `0/1`，其他值忽略。
- CAN ID、波特率和 I2C 地址的读取使用 `0x7065~0x7068`，不应从状态帧推断。

## 9. 主机通信流程示例

### 9.1 发现设备

主机 ID=`0x05`、广播目标=`0xFE` 时，可发送 `cmd_id=0x00` 的扩展帧并等待 `0x00`
响应。响应 bit15~8 是电机当前 CAN ID；收到后再用该 ID进行定向查询。

### 9.2 设置并验证扩展位置

设置目标圈数 `2`、圈内角度 `90.00 deg`、最大电流 `500 mA`：

```text
Data = 02 00 00 00 28 23 F4 01
```

其中 `9000 = 0x2328`，`500 = 0x01F4`。发送 `0x17` 后检查响应 cmd_para=`1`，
再发送 `0x18`、cmd_para=`0` 读取目标位置验证。

### 9.3 读取单参数

读取固件版本 `0x7060` 时，发送 `0x11`，Data 为：

```text
60 70 00 00 00 00 00 00
```

响应 Data0~1 回显 `60 70`，Data4 返回 `03`，Data5~7 为 `0`。

### 9.4 周期状态监控

主机可按需要周期发送 `0x02` 查询；每次收到响应后先校验扩展 ID，再解析状态位、
模式位、错误位和 Data。控制命令的状态反馈不是独立 ACK，必须结合状态和参数回读
确认实际生效值。
